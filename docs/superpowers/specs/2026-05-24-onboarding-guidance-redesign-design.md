# 新手引导重构设计

## 目标

重构当前新手引导，让它真正承担“带玩家完成第一轮关键操作”的职责，而不是在界面上同时堆叠多套说明。

本次设计的核心目标有 3 个：

1. 新玩家第一次进入时，能快速理解这款游戏当天要做什么。
2. 玩家进入主界面后，界面在任意时刻只强调“当前这一步要做什么”。
3. 在不另起一套全新教程系统的前提下，复用现有 `tutorial_progress`、`TutorialManager` 和主界面 coachmark 机制完成重构。

## 问题定义

当前引导没有真正起到引导作用，根因不是“内容不够”，而是“同时存在太多教程声音”，导致玩家注意力被分散。

当前并行存在的引导载体包括：

- 独立的 `Day -1` 教程场景
- 主界面中央大尺寸教程覆盖层
- 顶部单行 `教程提示`
- 左侧 `教程目标` 区块
- 抽屉中的 `Guide` 回看入口
- 基于当前状态的 coachmark / pointer 提示

这些载体部分内容重复，部分时机重叠，最终结果是：

- 玩家能看到很多说明，但不知道现在应该先点哪里。
- 教程层长期占据主舞台，打断真实操作界面。
- 不同位置同时发声，界面显得乱。
- 玩家看过说明后仍然要自己重新寻找操作目标。

## 成功标准

重构完成后，首次体验应满足以下标准：

1. 玩家首次进入时只看到一段很短的欢迎说明，而不是完整的教学正文。
2. 进入主界面后，始终只有一个主引导载体负责告诉玩家当前一步。
3. 引导中的每一步都包含：
   - 现在做什么
   - 为什么做
   - 去哪里做
4. 当前步骤对应区域被明确高亮，非当前重点区域被弱化但不强制禁用。
5. 玩家完成一步后，引导立即切换到下一步，不弹出打断式大窗。
6. 玩家仍然可以主动回看教程，但回看入口是兜底能力，不再和主引导抢主舞台。

## 范围

本次设计只覆盖首次体验和主界面中的新手引导重构，不扩展到中后期教程、系统百科或长期帮助系统。

包含：

- `Day -1` 欢迎说明的职责重定义
- 主界面教程覆盖层、任务区、提示条、回看入口的角色重组
- 引导状态和展示优先级的最小调整
- 当前步骤的高亮 / 弱化规则
- 现有测试需要覆盖的行为变化

不包含：

- 大规模重构 `MainView.gd`
- 新增独立教程状态系统
- 重新设计所有玩法文案
- 中后期复杂系统的分层教学

## 现状约束

本设计需要遵守以下项目现实：

1. `TutorialManager` 已经基于 `GameState.community_state["tutorial_progress"]` 管理 Day -1 完成状态和四个首个动作标记。
2. `MainView.gd` 已经存在 coachmark / pointer 逻辑，能够根据当前状态判断引导目标。
3. `completed_day_minus_one` 当前同时承担了“欢迎页是否显示”和“教程是否完成”的语义，这会妨碍“欢迎说明 + 主界面单步引导”的新结构。
4. 项目交接文档明确不建议另起一套独立教程状态系统，因此应在现有 `tutorial_progress` 结构上做最小增量。
5. `MainView.gd` 是高风险文件，本次改动应聚焦于教程相关函数和构建逻辑，不做无关重构。

## 设计总览

整体方案采用“欢迎说明 + 主界面单线程引导”的结构。

### 阶段一：欢迎说明

`Day -1` 保留，但职责从“完整教程页”改为“首次进入时的短欢迎卡”。

欢迎卡只负责：

- 用一句话说明每天的基本循环
- 告诉玩家接下来会学习的 4 个关键动作
- 告诉玩家进入主界面后会一步一步带着做

欢迎卡不再负责：

- 展示完整分步骤教学正文
- 长时间占据视线
- 充当主要学习场景

按钮策略：

- 主按钮：`开始引导`
- 次按钮：`跳过引导`

其中“跳过引导”保留，但视觉优先级明显低于主按钮。

### 阶段二：主界面单线程引导

玩家进入主界面后，不再同时展示顶部提示、中央大教程正文和左侧大段目标说明。

系统在任意时刻只突出一个当前步骤。该步骤由现有教程进度和运行状态推导出来。

优先步骤链路如下：

1. 选卡
2. 合成
3. 摆放
4. 解决需求

每一步只显示一张“当前一步引导卡”，包含：

- `现在做什么`
- `为什么做`
- `去哪里做`

同时保留一个非常短的已完成进度列表，仅用于提供节奏感，例如：

- `已完成：选卡`
- `已完成：合成`
- `当前：摆放`

这里的进度列表不能重新变成长篇说明。

## 状态设计

### 现有问题

当前 `tutorial_progress` 至少包含：

- `completed_day_minus_one`
- `first_pick_done`
- `first_craft_done`
- `first_place_done`
- `first_problem_done`

其中 `completed_day_minus_one` 的语义过重，既影响欢迎层显示，又被外部逻辑拿来判断教程是否已过。

### 设计调整

保留现有 `tutorial_progress` 字典，不新增并行系统，但将职责拆开。

推荐新增或重定义为两个层次：

1. 欢迎层状态
   - `welcome_seen`
2. 引导完成状态
   - 继续复用现有四个动作标记
   - 当四个动作都完成后，可推导“首次主线引导完成”

兼容策略：

- 旧存档若只有 `completed_day_minus_one = true`，应被视为“欢迎说明已看过”。
- 旧存档仍然保留已完成动作标记，不强制重置。
- 代码中不再把“欢迎层关闭”直接等价为“教程全部结束”。

如果出于兼容压力必须保留 `completed_day_minus_one`，则应将其退化为“欢迎说明已完成”的兼容字段，而不是整个主界面引导的唯一总开关。

## UI 结构调整

### 1. `Day -1` 场景

当前 `DayMinusOneView.gd` 会读取 `day_minus_one.steps` 并完整渲染全部步骤正文。

重构后：

- 标题保留
- 副标题保留但缩短
- 不再逐条渲染完整 `steps.body`
- 中部只展示一句总说明和一个四步概览
- 主按钮改为 `开始引导`
- 跳过按钮保留但弱化

这个场景的目标不再是“讲清全部规则”，而是“把玩家平稳送进真实操作界面”。

### 2. 主界面中央教程覆盖层

当前中央覆盖层会在主界面里再次显示完整的 Day -1 教学正文，面积较大，长期占据视觉中心。

重构后：

- 取消常驻完整教程正文
- 中央覆盖层只允许承担一次性欢迎过渡，或者直接完全移除
- 一旦玩家进入主界面操作阶段，就不再显示完整教学大面板

这是本次“去乱感”的关键动作之一。

### 3. 左侧任务区

当前 `任务清单` 内含一个 `教程目标` 小节，渲染多行说明，同时下方还有设施列表。

重构后：

- `教程目标` 改为 `当前一步`
- 这张卡成为主界面教程的主载体
- 卡片结构固定为：
  - 当前动作标题
  - 为什么做
  - 去哪里做
  - 极短进度摘要

设施列表保留，但在新手前几步中属于次要信息，视觉上应弱于当前一步卡片。

### 4. 顶部 `教程提示`

当前顶部 `tutorial_hint_label` 和左侧任务区在语义上重复。

重构后：

- 取消顶部常驻教程提示文本
- 如保留，只允许在极少数异常兜底场景中出现

默认情况下，顶部不再承担教程说明职责。

### 5. 抽屉中的 `Guide`

当前抽屉中的 `Guide` 和主引导并列存在，容易让人误解这是教程主入口。

重构后：

- 保留该入口
- 重命名为更明确的“回看引导”或等价表达
- 功能定位调整为兜底帮助入口

它不再承担主流程教学职责。

## 当前步骤呈现规则

为保证“真正起到引导作用”，每一步都必须与真实操作位置绑定，而不是仅显示描述文案。

### 步骤一：选卡

当前一步卡：

- 现在做什么：从公告栏拿 1 张卡
- 为什么做：这是每天行动的起点，卡会进入你的手牌
- 去哪里做：顶部公告栏

界面反馈：

- 高亮公告栏
- 弱化其他次要区域
- 如果存在 coachmark，箭头或视觉焦点指向公告栏

### 步骤二：合成

当前一步卡：

- 现在做什么：把配方需要的卡放到合成区
- 为什么做：这样才能得到设施
- 去哪里做：合成区或带有快速合成入口的手牌卡片

界面反馈：

- 高亮合成区，或在可快速合成时优先高亮可操作卡
- 当前若已有 1 张卡在合成区，则文案改为“补上另一张”

### 步骤三：摆放

当前一步卡：

- 现在做什么：把合成出的设施放到桌面 / 地图
- 为什么做：设施落地后才会参与后续产出和服务
- 去哪里做：手牌中的设施卡与中间可放置区域

界面反馈：

- 高亮可放置区域
- 在有设施卡可拖动时，优先引导玩家从手牌把设施拖出

### 步骤四：解决需求

当前一步卡：

- 现在做什么：处理居民需求
- 为什么做：未处理的需求会在结算时产生压力
- 去哪里做：需求卡与对应服务建筑

界面反馈：

- 高亮需求卡区域
- 若暂无需求卡，则改为“推进到下一天，需求会出现”

## 弱化规则

为了让引导真正聚焦，需要对非当前重点区域做“降噪”而不是“封死”。

允许的弱化方式：

- 降低非当前重点面板的对比度或饱和度
- 折叠非必要文字说明
- 将次要功能入口放到抽屉或次级层
- 保持可操作，但不提供强视觉竞争

不建议的方式：

- 全面禁用其他功能
- 用多个弹窗强迫玩家逐步点击关闭
- 在完成一步后弹出新的大面板阻断操作

本设计强调“引导视线和手势”，而不是“严格脚本化锁死界面”。

## Coachmark / Pointer 策略

项目当前已经存在 `get_active_tutorial_coachmark()` 及相关 pointer 刷新能力。

重构后建议：

1. coachmark 继续作为当前步骤的目标推导层
2. coachmark 只服务单一当前步骤
3. 当前一步引导卡与 coachmark 文案需要同源或高度一致
4. 不再让完整 Day -1 正文和 coachmark 同时承担教学主体

也就是说：

- coachmark 负责“指向哪里”
- 当前一步卡负责“解释为什么”
- 欢迎卡负责“建立心理预期”

三者职责必须清晰分开。

## 数据与文案策略

当前 `data/tutorial.json` 中的 `day_minus_one.steps` 和 `inline_hints` 仍然有价值，但需要重新分工。

推荐分工如下：

- `day_minus_one`
  - 用于欢迎卡标题、副标题和四步概览
- `inline_hints`
  - 退为兜底文案来源，或为当前一步卡提供短句
- 主界面当前一步卡
  - 建议使用更短、更动作导向的文案，不直接复用大段 `body`

文案原则：

- 动词开头
- 一次只说一个动作
- 避免规则百科式长句
- 避免同一信息在顶部、中央、侧边重复出现

## 兼容性与迁移

### 存档兼容

本次设计必须保持旧存档可读。

要求：

1. 旧存档未包含新字段时，应使用默认值补齐。
2. `SaveManager` 恢复 `tutorial_progress` 时，不应因缺少新字段而报错。
3. 对于已完成旧教程的存档，不强迫重新跑欢迎页。

### 运行兼容

如果外部逻辑仍调用现有 `TutorialManager.should_show_day_minus_one()`，需要更新其语义，使其只负责欢迎层显示时机，而非整个新手引导总开关。

主界面的当前步骤是否存在，应由：

- 欢迎层是否看过
- 四个动作标记是否完成
- 当前运行状态

共同决定。

## 实现建议

为控制风险，推荐按以下顺序落地：

1. 调整 `tutorial_progress` 语义和兼容补齐逻辑
2. 缩减 `DayMinusOneView.gd`，改成欢迎卡
3. 移除或停用主界面中央完整教程覆盖层
4. 将左侧 `教程目标` 改造成当前一步引导卡
5. 停用顶部重复教程提示
6. 接线现有 coachmark / pointer，让其与当前一步卡一致
7. 保留并重命名回看入口
8. 完成测试与手动回归

这条顺序优先解决结构混乱问题，再处理视觉指向问题，最后补验证。

## 测试设计

至少需要覆盖以下验证：

### 自动化

1. `tutorial_progress` 在默认状态下会补齐新字段。
2. 旧存档加载后不会因为缺少新教程字段而失败。
3. 欢迎层状态与四个动作标记语义分离。
4. `get_active_tutorial_coachmark()` 在四个阶段仍能返回正确目标。
5. 完成全部四步后，不再返回首次引导 coachmark。

### 手动验证

1. 新开档进入时先看到简短欢迎卡，而不是完整教程长文。
2. 点击开始后，主界面只出现一个主引导区域。
3. 完成选卡后，引导立即切到合成。
4. 顶部不再重复显示教程提示。
5. 中央不再长期显示教学全文覆盖层。
6. 抽屉里仍能回看教程。
7. 跳过引导后，不影响正常开局游玩。

## 风险

1. `MainView.gd` 中教程逻辑和 UI 刷新高度耦合，移除中央覆盖层时要谨慎检查依赖。
2. 旧测试可能隐含依赖 `completed_day_minus_one` 的旧语义，需要同步更新断言。
3. 若当前任务区与设施列表复用过深，改造当前一步卡时可能需要小范围重排布局。
4. 若顶部提示被直接删除，需确认没有其他逻辑依赖该节点存在。

## 验收结论

只有在以下条件全部满足时，本设计才算落地成功：

1. 首次引导从“多处同时解释”变成“单线程带动作”。
2. 欢迎说明不再长期打断主界面。
3. 主界面只保留一个教程主声音。
4. 教程能够明确把玩家带到真实可操作区域。
5. 旧存档、现有教程进度和自动化测试边界仍然稳定。
